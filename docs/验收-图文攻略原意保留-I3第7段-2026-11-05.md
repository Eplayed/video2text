# I3 第 7 段验收：逐请求用量与回退

日期：2026-11-05。范围：T16 技术验收。头条 AI 海报与公众号图片消息各记自己的任务账，不把旧文章链路用量混入新图文。

## 设计参考（限时 5 分钟）

调研了 [OpenTelemetry Python 的作用域追踪接口](https://github.com/open-telemetry/opentelemetry-python/blob/main/opentelemetry-api/src/opentelemetry/trace/__init__.py) 和 [Langfuse 的用量与费用记录说明](https://github.com/langfuse/langfuse-docs/blob/main/content/docs/observability/features/token-and-cost-tracking.mdx)。借鉴“请求放在任务作用域下”和“实际 token 与推算费用分开记”的结构；本项目沿用现有 OpenAI SDK 钩子与本地文件，不引入外部服务或复制代码。

## 本段交付

1. `src/model_usage.py` 在每次请求发出前写入 `output/model_runs/<run_id>.json`，回包后补模型名、结果与 token。日志不写原文、提示词、API Key、错误详情。头条海报的拆稿、单页重拆、出图与公众号图片生成分别有账；母稿版本与源版本一并记录。
2. 新图文任务中的模型失败不会自动跳到候选池的另一模型。出图请求若超时或连接中断，不再自动发第二次生成请求；状态记为未知，提示先查平台账单。429 限流仍按原退避规则处理。全局非图文任务的既有候选池规则不变。
3. 任务状态与成品详情展示本次请求次数、已返回 token、缺失用量次数与费用未知状态。界面上“0 元”明确限于底图/排版，确认框说明文案变更可能触发语义复审。无合格帧时预览与确认框都按“纯文字攻略页”表述。
4. 海报草稿 `plan.json` 改为原子写入。新包成功接管后，上一版完整目录归档到本渠道 `_history/<summary_id>/`；提交失败恢复当前包，旧任务晚返回不得覆盖新版本。`V2T_ORIGINAL_GRAPHICS=off` 只拒新生成，不删除草稿和历史包。

## 用量字段契约

`model_usage` 为对象。`schema` 为整数版本；`run_id` 为字符串任务标识；`channel`、`stage`、`status` 为字符串；`summary_id` 为整数；`source_revision`、`mother_revision` 为字符串；`request_count`、`tokens_known`、`tokens_unknown_count` 为整数；`cost_yuan` 为数字或 `null`；`cost_status` 为字符串（`no_model_requests` 或 `unknown`）；`calls` 为对象数组，逐条含模型名、请求类型、状态和可空 token 数。只有确实没有发出模型请求时 `cost_yuan=0`；只要发出请求且拿不到供应商实账，就保持 `null`，不能拿底图估价冒充整单费用。成品 manifest 只写 `model_run_id`，详情接口按 ID 读取这份运行账。旧包没有该字段时继续只读。
