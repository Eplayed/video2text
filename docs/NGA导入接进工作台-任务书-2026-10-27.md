## 要做的三件事

### 1. 登记采集源（`web/app.py`，符号 `DB_ONLY_SHEETS`）

在 `DB_ONLY_SHEETS` 这个 dict 里加一项 `"NGA无限板块": "nga"`。
**注意**：`nga_forum.insert()` 写库时 `source` 存的是 **`forum`**（不是 `nga`），而库里现有 1105 行都是 `forum`。
所以要二选一，别两处各写一套：

- 要么这里登记值就用 `"forum"`（与存量数据一致，推荐，零迁移）；
- 要么统一改名成 `nga`，那要同时改 `nga_forum.insert()` 的 `source` 常量和一条 `UPDATE videos SET source='nga' WHERE source_sheet='NGA无限板块'`——
  改了要顺手确认来源派生与来源计数（`api_videos` 里按 `DB_ONLY_SHEETS.values()` 判断的那几处）不因此把 NGA 当成 Excel 侧来源。

顺手确认 `FIRST_PARTY_SHEETS` 那张一手源卡片里 NGA 的位（文档 10-20 预留的位是"暴雪官方卡旁边"）。

### 2. 采集中心加一张 NGA 卡片（`web/templates/index.html`，符号 `page-collect`）

**复用暴雪官方那张卡的 DOM 与样式，不要新设计一套。** 卡片要显示的四格全部来自
`nga_import.check(db, data_dir)` 的返回，别在界面里另算：

| 界面格子 | 取哪个键 |
| --- | --- |
| 库里合计 / 快照去重后条数 | `inDb` / `tidTotal` |
| 待导（今天还没进库的） | `pending` |
| 有正文的条数 | `withBody` |
| 最新发帖时间 | `latestPost` |
| 上次导入时间与结果 | `lastRun` + `lastNew`（`lastSnapshot` 用来解释"为什么今天没动"） |

后端配两个接口：

- `GET /api/nga/status` → 直接 `return jsonify(nga_import.check(str(DB_PATH), NGA_DATA_DIR))`
- `POST /api/nga/import` → `nga_import.sync(str(DB_PATH), NGA_DATA_DIR, backfill=False, force=True)`，
  把返回 dict 原样给前端；`error` 非空时按现有其它采集卡的错误样式显示，**不要静默**。

两条实现约束：

1. 导入实测 **0.36 秒**跑完 1095 条，所以**同步返回即可，不要占那个"同一时刻只允许一个采集任务"的互斥闸**
   （那边正在写的 B 站采集/补转写用它，别为一次本地文件读取去排队或互相 409）。
2. `NGA_DATA_DIR` 与采集侧同一个环境变量，默认 `~/.nga/data`；界面顶部把当前路径显示出来——
   换了机器或改了目录，"pending 一直不为 0"就是这一格的问题，不是采集器坏了。

### 3. 每天自动导一次

现有 `config/sync_tasks.json` 的定时器是**工作台进程内**线程，工作台没开就不跑；
而 launchd 那侧每天 08:40 / 20:40 必然跑。所以定时挂在哪儿，两个选法：

- **推荐（采集侧一行）**：在 `wow-forever-web/tools/nga-daily.sh` 每次成功之后追加
  `python3 "$V2T/src/nga_import.py" --db "$V2T/output/video2text.db"`，抓完就导。
  不依赖工作台开不开，且导入本身幂等、失败只影响这一次。代价是 wow-forever 的脚本里出现另一个仓库的路径，
  要用变量给、路径缺失就跳过并在日志里写清"没找到 video2text，本仓库快照照常产出"，**不能因为导入失败而让采集报错**。
- 备选（工作台侧）：给 `sync_tasks` 加一类"导入任务"（区别于订阅同步），沿用现有"过点补跑"语义。
  代价是工作日没开工作台那天就不导，界面数字会比实际落后，得在卡片上写"上次导入时间"来暴露这件事（第 2 件已经要求显示）。

不管选哪个，都**不要**改成系统 cron，也不要引入新依赖。
