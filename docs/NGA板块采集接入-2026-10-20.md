# NGA 无限板块采集接入（`src/nga_forum.py`）

**日期**：2026-10-20｜**改动范围**：只新增两个文件（`src/nga_forum.py` + 本文件），
**没有动** `src/content_store.py`、`web/*`、`CHANGELOG_FOR_AI.md` —— 这些在我开工时是别的会话的脏文件，
按并发纪律不夹带。因此本模块**自己直写 `videos` 表**，字段口径照 `content_store.insert_official_news`。
要接进工作台 UI（`web/static/schedule.html` 那张「暴雪官方」卡旁边）留作下一步，等那边收工再说。

## 它是什么

素材库里新增一档 **`source_sheet = "NGA无限板块"`**，把 NGA「魔兽世界：无限」板块（fid=510569）
的**玩家帖子**当成选题素材收进来。库里原先只有 6 档（抖音视频数据 977 / B站视频 111 / 微信文章 95 /
抖音图文 22 / 暴雪官方 19 / AI面试 3），**论坛来源是 0**——`blizzard_news.py` 补的是官方口径，
这一档补的是"玩家到底在问什么"。

跑法与暴雪那路一致：

```bash
python3 -m src.nga_forum --pages 1 --limit 5 --dry-run   # 只抓不写库
python3 -m src.nga_forum                                  # 默认翻 2 页、本轮最多 40 条正文
```

实测（2026-10-20 18:0x 本机）：dry-run 列表 46 条 / 取正文 3 条 / 0 错误；真跑 `--limit 5` 入库 5 条，
再跑一次跳过已知、取了后面 5 条 → 库里 10 条、`COUNT(*) = COUNT(DISTINCT aweme_id) = 10`、
`source_row` 连号到 10。**判重生效，没有重复行。**

## 字段口径

| 列 | 取值 | 为什么这么填 |
| --- | --- | --- |
| `aweme_id` | `nf` + URL 的 md5 前 16 位 | 跟暴雪官方同一套思路（论坛帖没有 bvid 那种原生 id），去重键是 URL |
| `source_sheet` | `NGA无限板块` | 与「暴雪官方」分开，下游能一眼分清官方口径与玩家口径 |
| `source` | `forum` | 库里已有 `official` 这一类值，论坛另起一档 |
| `category` | `论坛选题` | 工作台按分类筛时不会被当成资讯 |
| `status` | 有正文记「已完成」，正文为空记「未开始」 | 沿用 `insert_official_news` 的规矩，不拿导航文案凑数 |
| `transcript` | 首楼正文（纯文本，UBB 与 HTML 标签洗掉） | 只有首楼；回复楼层没解析，别当整帖读 |
| `remark` | 「论坛素材：只当选题参考，不得成段引用或改写冒充本站观点」 | 见下面那节 |
| `published_at` | 首楼发帖时间（`postdate0`） | 页面给的就是 `YYYY-MM-DD HH:MM` |

## 一条必须一直带着的边界

帖子正文是**玩家原创**。wow-forever 仓库根 `AGENTS.md` 第五节的第三方取数边界写明：
只取事实性标识符，**不复制他人描述文案与攻略正文**；这条线的现行口径是
「**NGA 只当选题雷达，不上页面**」（2026-10-18 站主拍板，见那份 `网页端放开清单` 第 4 条）。

所以这一档进的是**素材库**，不是**发布链**：可以拿来看"哪块资料缺答案、玩家在吵什么"、
可以当选题依据，但**不许成段引用、不许改写冒充本站观点、不进小程序**。
这个约束写进了每条记录的 `remark`，就是为了让下游（写稿那一步）也能看见，
而不是只留在这份文档里。

反例已经在数据里出现过：热帖里有人自述「发帖太集中触发系统风控，新帖发出会被自动删除」——
论坛侧对集中自动化行为是真会动手的，本模块默认座间 1.5 秒、单轮最多 40 条正文、
连续 6 次失败自动收手（用的是号主本人登录态，硬打等于拿账号信用换数据）。

## 技术要点（都是撞出来的，别再撞一遍）

- **响应是 GBK**：`requests` 的 `r.text` 会乱码，必须 `r.content.decode("gbk","replace")`。
- **302 不是失败**：PHPWind 用 302 刷新 `lastvisit/lastpath`，必须 `allow_redirects=True`
  并且用同一个 `Session` 把轮换的会话值带回去。不带就会表现为"前几条成功、后面全挂"，
  很容易被误判成被风控（wow-forever 那边同一个坑已经踩过一次）。
- **登录态是必需的**：访客态 `read.php` / `thread.php` 一律 403（响应标题「访客不能直接访问」）。
  唯一稳的访客入口是 App 的 `subject/hot` 接口，但它固定 ~32 条、且**加任何分页参数会返回 0 条**。
- **cookie 只从仓库外读**：`NGA_COOKIE_FILE` 环境变量 → 默认 `~/.nga/cookie.txt`。
  按本仓库纪律 3（运行数据与密钥不入库），**不要放进 `config/config.env`**。
  文件里缺 `ngaPassportUid`/`ngaPassportCid` 会直接报错退出，不静默降级。
- **解析器 `ROW_RE` 依赖列表行结构**：某页解析到 0 行时脚本会明说"板块改版了，先别加量，回去核 ROW_RE"，
  并停在那一页，不会把空结果当"今天没人发帖"。

## 与 wow-forever 那套脚本的关系

**（2026-10-27 改口，推翻上一段"别互相导数据"）**：同一个板块两处抓会撞 PHPWind 登录态风控，
而两边对不上数（launchd 侧 1104 个 tid，这条库只有 10 条）。现在定成一条线：

- **采集只有 wow-forever 的 launchd 那一份**（每天 08:40 / 20:40，落 `~/.nga/data/board-*.json`）。
- 本仓库用 `src/nga_import.py` **只读那份 board 快照**（列表层：tid / 标题 / 作者 / 发帖时间 / 回复数 / url，
  正文从 `threads/<tid>.json` 取），导进 `videos` 表。除此之外不导别的——
  `view.html`、`index.json`、资料站的成品基底与 upstream 原料都不进这条库。
- `nga_forum.py` 退回**手动救急**：默认不联网，要自抓必须显式加 `--fetch`。
  它的 `post_id()` / `insert()` 仍是唯一写入口径，导入器复用它们，所以两条线不会出现同帖不同键。

原来那条担心依然成立，只是换了防法：**素材库是给人看的选题池，资料站基底是带溯源进页面的成品**，
两者不共用一张表；导入进来的行靠 `source_sheet='NGA无限板块'`、`category='论坛选题'`、
`remark` 那句用途标注三处自证身份，下游取素材时看得见"这是玩家原创，只当线索"。
