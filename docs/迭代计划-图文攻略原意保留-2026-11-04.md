## 3. I1：一次改完整条“内容迁就模板”的链

交付内容：取消强制对比/提醒/互动/页数/同构限制，修改 prompt、schema、normalize、lint 的一致约束；清理字段裁剪、末位删卡、余页截断和渲染截行；匹配不到图不再自动塞无关图。

本轮可独立交付增量保护，但不宣称“原意完整性已验证”：母稿与覆盖映射在 I2 才接入。达技术上限必须明确错误与恢复入口；新预览可以显示溢出草稿，正式导出不准带截字。首批用 1 条新素材同时查看原文与两渠道预览；如果只覆盖海报一端，应明确标注公众号未验，不能报双渠道完成。

必验：无对比清单、最后一条关键前提、超长说明/标题/尾注、无图文字页、无关高清图、2 秒间隔连续动作、失败恢复、旧包读取。既有合法对比、风险提醒及截图仍应正常显示，不能通过全部删除部件逃避测试。

## 4. I2：把整理稿替换为原意母稿

交付内容：新图文直接从完整原始转写提取母稿；保留作者答案、必要条件和原句定位；图文拆页直接消费母稿；两个逻辑加工阶段，不再长文扩写后压缩。

必须覆盖两个入口：素材生成和排产任务生成。源文本标题/标签可参与定位，但不能用它们证明正文没有的事实。原文无时间戳用段落，不推测秒数。来源缺失不允许把生成稿自证为事实。

检查独立于生产答案：必保点 ID 覆盖、语义忠实性、外部事实状态分别呈现。母稿修订影响派生包版本，审核不能跨版本沿用；已有成品不自动覆盖。

必验：长文结尾关键点、失败段续跑、两主体限定、观点概率、核心条件遗漏、手工改稿后失效、较旧后台任务晚返回、缺源与无 AI。母稿版本状态在 I2 开工前定稿、T10 完成，不留到 UI 末尾补救。

## 5. I3：两渠道成为一条可用主流程

交付内容：公众号图片消息复用母稿，按 3:4 独立分页；头条按 9:16；各自标题、配文和签审。现有公众号文章模式保留。

预览显示核心答案、信息分布和具体疑点，点问题跳源文与页面。皮肤/字号/尺寸调整不重写内容；错误后仍能看见已编辑稿。生成进度、用量和实际请求一致。

统一当前规则：检查项目内角色技能、实际注入提示词、图形 lint 与 UI，消除强制新角度、必须有图、固定页数等旧要求对新模式的覆盖。不是删除全部编辑纪律；来源归属、真实感与人工发布仍保留。

用后续三条新素材完成两渠道六包真实验收。先人工标必保点，再生成；保存原文版本、模型/规则版本、实际结果及逐项问题。未过则定点修复，不用反复生成挑到一版好看就算通过。
