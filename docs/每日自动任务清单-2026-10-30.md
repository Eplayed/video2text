# 每天自动执行的任务清单（2026-10-30 全量实测）

为什么要这一份：号主问「数据与同步每天都会更新素材吗」，查下来发现**自动跑的东西散在四个地方**——
工作台进程里的定时器、系统 launchd、cron、Qoder 定时任务。只看工作台那一屏会以为只有 6 条，
实际不止；而**没在这一屏上的那几条，坏了也没人知道**。本表每一项都带"今天/最近一次实测到什么"，
不是照配置抄一遍。

口径：只列**会自动跑**的。手动按钮（海报「补画面」、CLI 采集、发布登记）不算，但第 5 节列了
三件"看着像有、其实没有"的，防止当成漏。

## 2. 工作台进程里的定时器（6 个任务 / 2 个 60 秒轮询）

代码：`web/app.py` 的 `_autosync_tick`（订阅与源类任务）与 `_planmatch_tick`（夜间匹配），
都是 `while True: sleep(60)` 的守护线程，**跟着 Flask 进程活**。

| 任务 | 频率/时刻 | 今天实测 |
|---|---|---|
| 魔兽世界（7 个订阅） | 每天 07:30 | 07:35 跑成功，新增约 5-6 条（尤安 1、一起玩魔兽 1、夏一可 1、泰莉亚 2…） |
| 抖音 1 个号（好赛雷切片） | 每天 07:30 | 07:35 跑成功，无新投稿 |
| AI（4 个订阅） | 每 2 天 07:40 | 上次 10-29 07:42 成功，下次 10-31 |
| 微信 5 个号 | 每天 09:30 | 09:30 成功，新增 3 篇；**另有 35 篇"全文未就绪"，下次自动重试** |
| 暴雪官方公告 | 每天 10:10 | 10:10 成功，列表 20 条、新增 0 |
| NGA 快照导入 | 每天 10:40 | 10:32 手动跑通：1105 → 1414 条（+309） |
| 排产夜间匹配 | 每天 22:00 | 上次成功 10-29 22:00；10-30 上午手动跑过一轮 |

**这一组的三个要害**：

1. **工作台没开 = 这 7 条全不跑**。过点之后把工作台开起来会补跑（到期判据只看"设定时刻过了没有"），
   但**夜间匹配的补跑只往前看昨晚一次**（`CATCHUP_LOOKBACK=1`）——连着关三天不会补三轮。
2. 新素材**当天就带转写与帧池**：订阅那条抖音链路走 `collector.process_row → asr_transcribe`，
   删掉 mp4 之前会调 `frame_pool.build`（10-30 那轮 6 条新视频每条都有帧池目录）。
   **B 站这一路 11-01 才接上**（之前只入元数据、转写要人点、帧池从来没有）：同步抓完会自动起一个
   后台作业走「下整片 → 本地转写 → 抽关键帧 → 删片」，超 20 分钟的只转写不抽帧，
   超 45 分钟的整条跳过。回执里会写「已自动接上本地转写+抽关键帧（N 条…）」，
   作业槽被占时点名"排在下一轮"，不静默丢。
3. 转写档位 10-30 起三条采集路共用 `ASR_MODEL_DEFAULT = "small"`；以前订阅那条写死 `base`。

- **B 站自动链真的自己跑了**：07:31:52 起作业，Tony兔兔鸡 18 条转写 + 324 张关键帧，0 元。
- 第一次跑就撞出一个设计缺陷：**B 站作业槽同时只容一个作业**，第二个号（漫步魔兽 20 条）07:40 来起
  作业时撞槽，回执写"排在下一轮"，结果那个号当天一条没转写。已改成**一轮攒队列、收尾起一个作业
  按号排队**（`_bili_chain_queue` / `_bili_chain_flush`）；不并行是故意的（8 核，两个 whisper 同跑
  只会一起变慢）。同轮还修了补帧档的取数窗口（原来按"最新 N 条有正文"取，积压老料永远在窗口外，
  回执会写成"0/0 条抽出 0 张"这种看着像跑过的样子）。
- 这台机器当天 09:10 负载一度 **44**（8 核）：来源是那趟自动转写吃满核 + 别的会话反复起 headless
  Chrome（puppeteer），不是卡死的作业——判据是作业槽 `running=false`、同步槽 `running=false`。
  **自动转写这一档会实打实占满 CPU 几十分钟**，号主要在这段时间干重活的话得知道这件事。
- 数据卷空闲 29GB → 25GB（当天上午），**不是这条链造成的**：它全天只多占约 900MB 帧池、
  临时目录零残留；链自己的底线闸是空闲 6GB。
