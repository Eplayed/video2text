# 发布前体检（审核角色）

## Overview

现成两个质检器各有盲区，实测同一份产物结论互相打架：`verify_toutiao.js` 报正文 866 字、禁用句式 2 处，而 `ai_score.py` 给 7.9/100「真人味」——因为它把发布元数据和图池当正文一起算了。**"机器说没问题、人一眼看出是 AI"缺的就是这一层**：先切出真正文，再补三项判断。

判定标准来自三份权威源，本技能不复制规则表：

- 句式黑名单：`media-workbench/server.js` 的 `BANNED_PATTERNS`（`verify_toutiao.js` 动态切片读取）
- 写作原则：`~/Documents/自媒体/ARPG去AI味写作规则-v7.md`（第一原则：不要装得比实际更懂）
- AI 味评分：`_content_factory/wechat-publisher/scripts/ai_score.py`

## 用法

```bash
# 长文稿（Dify 产物 .md）；--sources 给对应的整合稿，用于数字出处核对
python3 scripts/audit_draft.py ~/Documents/自媒体/_content_factory/dify/scheduler/auto_out/<日期>/1_*.md \
        --sources temp/整合稿.md

# 图文卡稿（4 张卡 + 微头条文案）
python3 scripts/audit_draft.py --manifest output/toutiao/65
```

退出码：`0` 可以发 / `1` 改完再发 / `2` 不能发。

## 三项机器查不到、必须人判的点

1. **中间产物泄漏**：`图1：画面说明`、`配图任务：打开 https://…`、`**增量：**`、`发布状态：需手改 N 处`、`视频1`、`来源：整合稿`——这些是给机器看的指令，混进正文就是用户说的"乱七八糟"。命中即不能发。
2. **叙述者缺席**：正文里没有一个带具体动作的「我」（我把/我试/我核/我算/我翻）。全篇只剩「制作副总监强调」这种转述，就一定是通稿腔。长文稿命中即不能发；图文卡稿只查 `copy_text`（卡片是短句清单，降级为建议）。
3. **数字有没有出处**：正文里 ≥2 位的数字，逐个回整合稿/素材里找。找不到的一律标出——要么补来源，要么删。**严禁用"编数字"的方式让稿子显得具体。**

## 输出纪律（不许只报分数）

必须给三选一结论 + 逐条「必须改 → 问题：细节」。分数只是其中一项依据，不是结论。
AI 味评分 ≥45 判 FAIL、30–44 判 WARN（阈值与 `ai_score.py` 的 `DEFAULT_THRESHOLD` 对齐）。

## 已知边界（如实告知，别当已通过）

- `--sources` 必须给**同一选题**的整合稿，否则数字出处会误报一堆。
- 图文卡稿模式下卡片文字太短（每条 ≤30 字），AI 味评分天然偏低，**分数低不等于有人味**，此时以「叙述者缺席」和「编辑向交代」两项为准。
- 体检只判形，不判对错：游戏机制本身对不对，仍要按整合稿【风险核查】人工核。
